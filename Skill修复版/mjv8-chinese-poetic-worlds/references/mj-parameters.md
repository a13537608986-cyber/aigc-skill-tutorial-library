## 用户设置与默认值怎么合并

按“用户本次明确要求 → 用户当前成图及任务阶段 → 本Skill主文默认值”处理。用户说竖版就改画幅，要求纯文字就不给后缀，已在图生视频阶段就不再附MJ参数。主文较早的2026-09-11版本说明是历史记录，本次核验日期以本页为准。

| 项目 | 没有用户覆盖时的主文约定 | 应怎样修改 |
| --- | --- | --- |
| 画幅 | `--ar 16:9` | 用户明确9:16、3:4或21:9时使用该值；成图阶段继承实际图裁切 |
| 图片版本 | `--v 8.2` | 用户明确指定其他版本时保留其意图，并另核对该版本可用性；不偷偷换模型后仍称原模型 |
| 风格控制 | `--raw` | 遵循用户显式选择，不把它解释成已保证写实 |
| Stylize起点 | `--s 100` | 是主文建议起点，50–100或150–250是待试的创作选择，不是复刻成功率证据 |
| 排除项 | 简短排除文字、水印、标识、动漫等 | 用户需要文字、动漫或特定标识时删掉对应排除项；不要与正文硬性需求互相冲突 |
| 风格参考 | 默认不附虚构URL | 实际有可访问图片URL才添加；只有本地文件时用网页上传说明，不把本地路径写成URL |

## 可复制的起始后缀

这是主文的起始设置，应用前先合并用户要求；它不包含上传图片或实际运行记录。

```text
--ar 16:9 --v 8.2 --raw --s 100 --no text, watermark, logo, anime, cartoon
```

如果用户要9:16动漫插画，应替换为对应画幅，并删除 `anime, cartoon` 排除项；不能一边写动漫正文，一边要求排除动漫。若用户要求画面内品牌标识，应移除 `logo` 排除项，并使用用户提供的实际标识信息，不编新品牌。

## 使用风格参考时

1. 先实际查看用户给的图，挑一至三张风格相关且互不冲突的图是主文的创作建议，不是官方必须数量。
2. 没有线上图片URL时，只给完整文本提示词，并在代码块外说明将本地图片放入网页的Style Reference区域。不要放 `file://`、附件ID或“URL待填”等占位内容到最终复制块。
3. 已有真实可用URL时，才把它接在 `--sref` 后；`--sw 100` 可以作为文档默认起点。需要调弱或调强时，改变一个设置后看实际结果，不声称数值必然带来某种风格。
4. Style Reference不能代替人物身份控制。人物连续性仍需写清年龄、外形、发型与服装，不能承诺只靠文字或Style Reference百分之百锁脸。

本页不列虚构图片URL的可复制示例。用户没有提出高级引用功能时，不额外扩展Edit Model等分支。

## 本修复版不默认添加的内容

不自动附加 `--q`、`--cref`、`--oref`、正文多重权重 `::`、随机风格码、个性化档案、高混乱度或HD配置。其中V8.1/8.2的Quality、Omni Reference和普通Multi-Prompting限制已由上方Version页核对；其余“不自动添加”是本Skill的范围选择，不一概解释成所有版本都不支持。

普通正文Multi-Prompting的限制，不等于宣布所有位置的 `::` 写法都无效。本修复版不提供多图权重组合，避免把功能边界混为一谈。

## 平台不接受参数时的交付

交付完整英文正文，把目标画幅和希望使用的图片模型在复制块外列清楚，明确该平台需自行核对对应设置。不要猜第三方界面“MJ写实模式”一定如何映射官方版本，也不要把教程截图里出现的价格写成当前报价。

发出前检查：用户画幅是否被覆盖、正文与排除词是否冲突、有没有假URL、是否误把图片参数放进视频提示词。检查文本通过仍不代表平台执行或视觉效果通过。
