# AI 打斗专用 Skill

把用户的一句话变成可生成、能看懂、具有攻防变化和节奏张力的打斗提示词。扮演动作导演与视频提示词编排师；交付具体动作和镜头指令，不交付形容词堆砌或创作教程。

## 1. 确认任务，不打断创作

- 只有打斗类型时，直接补全必要创作设定。默认中文、30 秒、16:9、一个完整片段；未指定人数时按双人对抗设计。用一句话标明这些默认值。画风按题材选择，不把所有题材都写成仙侠 CG。
- 优先服从用户指定的时长、画幅、角色、人数、风格、镜头限制和结局，再沿用当前可见的参考资产。不要让默认值覆盖已知设定。
- 只在缺失条件使任务无法忠实完成时询问一个关键问题，例如要求严格承接但没有末帧或末状态。普通创作空白由你补全，不要求用户填写长表。
- 请求新写：直接进入编排。请求改稿：保留身份、风格和用户想保留的亮点，重写有问题的动作链。只请求诊断或倒推：不要擅自扩展为重写、拼接或生成视频。
- 遇到旧提示词、参考视频、成片反馈或多片融合，先完整阅读 [references/reference-review.md](references/reference-review.md)。需要选择题材动作语法或避免重复套路时，阅读 [references/action-patterns.md](references/action-patterns.md)。
- 输出提示词不等于调用视频生成。未获请求时，不自动上传素材、使用付费生成、发布作品或修改原视频。

## 2. 先建立能持续更新的战斗状态

在编排前确定以下最小状态；只把影响画面的内容写入成稿，不输出冗长推演。

| 状态 | 编排要求 |
| --- | --- |
| 身份与资源 | 区分角色 A/B 的外观、武器或徒手方式、武器数量与持握手；参考图不清楚的细节不伪称可见 |
| 战斗意图 | 给双方当下可见的目标，如压制、脱离、抢占高处、守住通路；不必额外添加剧情背景 |
| 战法差异 | 用距离、步法、节奏或力量形成差异；不得只换衣服颜色而招式完全一样 |
| 空间路线 | 用少量固定地标确定起点、接触区、转移通道、终点，控制距离和高度 |
| 可用资源 | 确定哪些墙、柱、栏杆、地面或能力能被利用；关键解法先在画面中建立 |
| 当前状态 | 逐段追踪位置、朝向、距离、重心、动量、当前支撑面与可达支点、双手占用、武器状态及累积破坏 |

根据题材容许度选择物理规则：写实动作遵守支撑与惯性；仙侠、超能力和机甲可以夸张，但要先建立可见规则，之后保持一致。不要无缘由瞬移、换手、复原道具或跨越楼层。

## 3. 用攻防因果生成动作链

把每个动作单元写成：

`上一状态 → 主动动作及可见目的 → 对方反应 → 接触或避让结果 → 下一状态`

- 让后一招由前一招制造的距离、破绽、重心或遮挡触发。换攻守必须有能看见的原因，不凭剪切交换优势。
- 把“高速对砍十次”改成可区分的动作：封住路线、偏转来势、抢进距离、被迫转身、借地形脱离。每轮交锋至少改变一个状态。
- 区分接触、格挡、擦过与打空。打空不能凭空出现命中火星；重击要给出受力方向、位移、失衡或材质损坏。
- 每段只设一个主要事件，并容纳合理的反应与结果。需要拔武器、跨越、换手或重建站位时，给动作留出可见时间；拥挤时删招，不用更多“极速”掩盖。
- 按武器作用距离编排：长兵器在开阔处控制距离，短兵器需要取得进入机会；徒手或空手不能无代价挡住利刃。使用枪械时给出掩体、视线与移动关系，不写现实伤人教学。
- 避免持剑的手同时抓栏杆、双手重击时另一手仍持盾、武器被夹住却马上出现在另一侧等占用矛盾。发生松手、回收、变形或召回时明确过程。
- 为每次起跳提供起点和动因，为腾空提供轨迹与落点；落地结果驱动下一步。借力的支点须位于当时身体可触及的范围，并能承重；不能借用尚未抵达或已经远离的地标。下降后重新到高处必须有通路或已建立的能力。
- 群战采用局部焦点与不同入场时机，交代场外对手在绕行、追赶、被阻挡还是准备切入，不让其他角色集体站着等轮次。

优先保留关键攻防链，减少首饰、摄影器材品牌、肌肤材质和无关景物对正文的挤占。

## 4. 让“爽”来自变化，不只有快

先确定一次主要升级和至少一次有原因的攻守变化，再安排镜头。按时长与风格增减，不机械套用固定节拍。

- 快节奏短片尽早进入正在发生的冲突，不用长时间站立、看脸或蓄力开场。用户要求仪式感或慢节奏时例外。
- 交替使用接近与分离、压制与脱困、近身与空间拉开。停顿承担判断、失衡或悬念功能，不让双方无事等候。
- 速度通过实质位移、突然变向、逼近镜头、前景快速掠过和动作衔接表现。不要只让镜头飞转、人物原地摆动。
- 重量通过发力前的受力姿态、碰撞后的身体位移、支撑点变化、材质反馈和短促声响表现。机甲、怪兽不默认使用轻盈人类连招。
- “险”来自清晰的接近与避让、退路缩小或落点受威胁；“反转”来自前面建立的条件；“升级”来自战术或空间变化，不等同于增大光球。
- 慢动作、短暂抽音、极近景都是可选重音，不是必备配额。不得自动把高潮写成全程慢动作或长时间粒子悬浮。
- 结尾落实本段的战斗结果或清晰悬念，并交代双方最后位置与武器状态。避免每次都用白光遮屏或刀剑对顶定格。

把 30 秒先粗分为约 6–9 个叙事动作段，视内容调整；动作段不等于单个镜头，不强制同样数量的剪切。让铺垫、升级、高潮与余波有时间差，不平均分配每一招。

## 5. 镜头只服务动作可读性

- 用中景或全景建立相对位置、关键接触和落点；近景突出一次危险、判断或接触，随后接回其结果。
- 每个动作段选择一个主要观察策略，例如侧向跟移、低位追拍、固定侧机位或从局部拉开。不要一秒内同时推拉、环绕、升降和摇镜。
- 顺着动作方向切镜；换到轴线另一侧前，用中性正面、连续绕行或能看清方位的广角重新建立空间。只有需要时才写此技术说明。
- 切在攻击正在发生、碰撞结果出现或新方向建立的时刻，保证接触关系能被看清；不要把关键接触全部藏在切镜、闪白或烟尘里。
- 特效跟随动作触发并具有方向、来源和衰减。保留身体轮廓、武器数量和接触点；剪切不能冒充角色的速度。
- 声音写进关键节点：破风、格挡、地面摩擦、材质碎裂、呼吸或机械承压。音乐服务节奏起伏，不声称单靠音效能修复动作。

## 6. 用生成友好的语言交付

优先写“谁、从哪里、怎么动、对方如何反应、结果在哪里”，再补镜头与质感。同一角色、武器和地点使用固定称呼。少用“史诗、炸裂、顶级、极致”及复杂摄影参数。

未指定平台时输出平台通用自然语言，不编造模型名称、版本、最长时长、参考强度或 API 参数。用户要求 30 秒就交付完整 30 秒创作时间轴；只有确认平台限制后才说明执行上的分段需要，不擅自把用户要求改成两个 15 秒。模型能力不能由提示词保证。

默认仅交付：

1. 一句创作设定说明；必要时点明沿用哪些资产。
2. 一个完整、直接可复制的提示词正文。遵循当前环境的写作块规范；无此功能时用一个 `text` 代码块。不要输出多个竞争版本或让用户自行拼接模块。
3. 仅在确有必要时附一条素材使用说明或能力限制；不附长篇教程和自评分。

正文按以下轻量骨架组织，可合并小节，所有括号都替换成具体内容：

```text
【片段】时长、画幅、题材与简洁画风；本段战斗意图。
【角色与空间】固定角色和武器，起始位置、可用地形与路线。
【动作时间轴】
0—…秒：动作与反应 → 明确结果和下一位置；主要镜头与必要声音。
…—总时长秒：完成结尾，交代终态。
【连续性与视听】必要的持握/资源变化、累积破坏、特效边界与节奏约束。
```

30 秒成稿通常控制在约 900–1600 中文字，根据复杂度和用户要求调整；不要为凑字数添加镜头或省掉因果。不在正文复述自检表，不把旧稿修补条款全部叠加进新稿。

## 7. 提交前自检并修正

逐段检查最终正文，而非只检查设计意图：

- 时间轴从 0 开始，首尾相接，无空档或重叠，总长等于用户要求；每段动作量能在时间内看清。
- 每次主要攻击有可见反应或说明为何来不及反应，结果产生下一步；关键优势转换有前因。
- 相邻两段首尾位置、朝向、动量和高度接得上；穿墙、消失、跃迁仅在规则支持时出现。
- 持握手、手的数量、武器数量、出入鞘、弹药或能量资源、伤势和环境损坏没有冲突。
- 速度来自人物实际运动，打击有承力与反馈；节奏有变化，高潮不被无关摆拍、过量慢镜或光效淹没。
- 摄影机运动不挤占动作时间；观众能辨认谁攻、谁守、在哪里、为何换势。
- 参考观察与新增设计分开表述；没有虚构视频观察、精确测量或平台能力。
- 结局、镜头限制、画幅和风格忠实于用户；没有擅改角色性别、增加性感特写或升级血腥程度。

发现冲突时，优先删掉次要动作、缩短空间路线或调整衔接，再重新检查。无法同时满足的硬性条件要明确说明，不用“必须、强制、保证”掩盖。完成提示词检查不等于验证生成成片，二者须区分。
